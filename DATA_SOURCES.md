# Джерела даних Kharkiv GO

Цей документ пояснює, звідки походять дані застосунку і чому вони зберігаються
локально (`src/data/*.json`), а не завантажуються з живого API.

## Чому дані локальні, а не "живі"

Kharkiv GO спроєктовано як **offline-first застосунок без бекенду**
(вимога проєкту: "Работать без backend. Только JSON, IndexedDB, LocalStorage",
"Повна сумісність з Telegram Mini App і GitHub Pages"). Це принципове рішення,
а не тимчасове обмеження:

- **Немає офіційного відкритого API/GTFS для Харкова.** КП «Харківський
  метрополітен» публікує розклад лише як HTML-таблиці на metro.kharkiv.ua —
  без машиночитаного формату (JSON/GTFS). Наземний транспорт (гортранс)
  офіційного відкритого фіда також не публікує.
- **"Живий" бекенд суперечив би вже узгодженій архітектурі** — Telegram Mini
  App і GitHub Pages деплой не мають серверної частини, яка б проксувала
  запити (і обходила CORS чужих сайтів).
- **Рух метро свідомо порахований за розкладом, без GPS** (див.
  `src/metro/`) — це була явна вимога проєкту, а не заміна "поки немає
  живих даних".

Тобто "реальні дані" тут означає: **факти, перевірені за офіційними та
авторитетними джерелами й зафіксовані у структурованому JSON**, а не
"дані, що надходять по мережі в реальному часі".

## Що перевірено (трамваї/тролейбуси) — і що ще ні

- Кількість трамвайних ліній у наших даних (12–13 унікальних номерів,
  залежно від того, рахувати 16 і 16а окремо) відповідає офіційній
  статистиці **"Number of lines: 12"** з [Trams in Kharkiv — Wikipedia](https://en.wikipedia.org/wiki/Trams_in_Kharkiv).
- Номери й кінцеві станції автобусних/тролейбусних маршрутів (163 записи
  в `routes.json`) **не пройшли повторну повну перевірку** в рамках цієї
  сесії — їх занадто багато для ручної звірки без доступу до офіційного
  Overpass/GTFS API (недоступний з цього середовища). Якщо потрібна повна
  звірка всіх маршрутів наземного транспорту — це окрема велика задача
  (сотні пошукових запитів), яку варто робити партіями.

## Як оновлювати дані надалі

Якщо з'явиться офіційний машиночитаний розклад (наприклад, GTFS-фід),
його можна імпортувати офлайн-скриптом у ці самі JSON-файли — архітектура
`src/metro/` це підтримує без змін коду (рушій лише читає
`routes.json`/`stops.json`, звідки б вони не походили).
